The Problem

The alert that matters
is already buried.

Every company running security tools generates thousands of alerts daily. Each arrives as a single line demanding a human decision. No analyst can process five thousand rows per shift — so they stop trying. The moment they stop, the alerts stop protecting anyone.

SIEM ALERT FEED — soc-monitor-01

01 / VOLUME

Volume destroys signal

When everything is flagged, nothing is. A critical exfiltration alert and a routine login share the same line on the same crowded screen.

02 / CONTEXT

No context per alert

Each alert arrives isolated. An analyst must manually gather logs, location, user history, and correlated events before making any judgment.

03 / FATIGUE

Fatigue leads to muting

Overwhelmed teams silence entire alert categories to get through the shift. The silence is precisely where real attacks operate undetected.

04 / COST

Legacy platforms are prohibitive

Enterprise SIEM platforms cost hundreds of thousands per year, require dedicated teams to maintain, and still route your data through their infrastructure.

The Solution

Avekshak reads them all
so you never have to.

Instead of routing raw alerts to a human queue, Avekshak does the first pass — groups related alerts into a single incident, dispatches an AI investigator, and surfaces only what demands a decision.

01

Correlate related alerts into one incident

Forty alerts from the same attacker across ten minutes collapse into one incident — not forty separate decisions.

02

AI agent investigates each incident

The agent checks logs, geolocation, user history, and behavioral patterns, then produces a plain-language verdict with a confidence score.

03

Every reasoning step is recorded

Evidence, queries, and conclusions are written to an immutable ledger. The decision is never a black box.

04

Nothing acts without human approval

The AI proposes. The human decides. No account locked, no server isolated until an analyst approves the action.

05

Runs entirely inside your perimeter

The LLM runs locally via Ollama. Zero data leaves your network, zero API keys, zero per-query fees.

The Pipeline

One event. Five services.
One verdict.

The real services, real queues, and real database behind every security event Avekshak processes.

services/ingest
Connector pollers pull raw events from cloud accounts, syslog, and security agents. Every source — regardless of vendor — is normalized into a single NormalizedEvent shape defined in @avekshak/schema.
{ id, ts, source, category } { action, outcome, severity } { actor.ip, actor.user } { target.host, target.resource }
Redis queue · "events"
services/fusion
Every normalized event is evaluated against every detection rule. Two engines run in parallel:
Promoter (single-event)
One event satisfies a rule condition → alert fires immediately via promoter.ts
Threshold (temporal)
Redis counter per key; alert fires when count exceeds N within the window via threshold.ts
alerts → Postgres dedupeKey window: 5 min
Redis queue · "alerts"
services/correlation
Groups related alerts into a single incident using a correlation key — the shared actor IP, user account, or target host. Fifty alerts from the same attacker become one incident, not fifty separate decisions.
incidents table incident_alerts table ledger table
Postgres · incidents table
services/agent
Reads each new incident. Sends full context to the local LLM — event details, the rule that fired, actor telemetry, and behavioral pattern — and receives a structured verdict:
Escalate
Confirmed threat — needs human now
Investigate
Needs additional evidence
Close
Benign — auto-filed to ledger
incidents.verdict ledger entry per step Ollama · local LLM
HTTP · services/api
Human Analyst
Sees a concise list of investigated incidents — not thousands of raw alerts. Reviews the AI's full reasoning chain, evidence trail, and confidence score. Approves or rejects the proposed action. Nothing is blocked or modified until this step completes.
approvals table ledger · append-only audit trail
Shared Packages
@avekshak/db
Single source of truth for the Postgres schema and getDb() connection factory. No service defines its own tables independently.
@avekshak/queue
Thin Redis wrapper. createQueue("events").enqueue() / .consume() keeps every service fully decoupled.
@avekshak/schema
TypeScript types for NormalizedEvent. Ingest produces it, fusion consumes it — both sides always agree on the contract.
MVP Scope

What ships first,
and what waits.

The first version proves the full loop end to end: real data in, correlated incidents out, AI verdict on each, human approval before any action.

In the first version
  • Three data connectors: cloud logs, server logs, syslog
  • Detection engine with high-value security rules
  • Alert correlation into incidents — the central feature
  • Local AI agent that investigates and writes verdicts
  • Immutable investigation ledger for full transparency
  • Human approval step before any response action
  • Incident dashboard and approval UI
Deliberately deferred
  • Extended connector library (dozens of sources)
  • Large-scale data lake and graph storage layer
  • Automated response playbooks
  • Enterprise SSO, MFA, multi-tenant isolation
  • Shared threat-intelligence network
  • Behavioral analytics and deception tooling
